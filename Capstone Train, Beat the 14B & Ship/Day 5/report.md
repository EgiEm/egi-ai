## 1. Problem

OXODIN's production intent router runs every user utterance through **Qwen3-14B-AWQ** — a 14-billion-parameter LLM served via vLLM on an L4 GPU. It classifies sentences across six intents: `place_call`, `create_task`, `set_timer`, `answer_question`, `save_memory`, and `out_of_scope`. The model is accurate, but it takes **~3.4 seconds per classify call**. At scale, that latency is a bottleneck — it blocks the voice pipeline, burns GPU hours, and makes the assistant feel sluggish to users. The question: **can a small, fast, purpose-trained router match the 14B's accuracy at a fraction of the cost?**

---

## 2. The Contract

Two gates, both required. No exceptions:

| Gate | Rule | Threshold |
| :--- | :--- | :---: |
| **Speedup Floor** | Candidate p50 latency must be ≥10× faster than the 14B baseline | ≤ 340 ms |
| **Accuracy Margin** | Golden set accuracy drop must be ≤ 2.0 percentage points | ≥ 83.0% |

A candidate that is fast but inaccurate **fails**. A candidate that is accurate but slow **fails**. Both gates must light GREEN on the same frozen golden set to pass.

## 4. Your Model

Three rungs on the ladder, each one building on the last:

1. **SetFit (Day 2):** Sentence-transformer body (`all-MiniLM-L6-v2`, 384D embeddings) + logistic regression head. Trained on 48 examples. First player on the field — fast, but rough around the edges.

2. **Distilled Student (Day 3):** Same architecture, retrained on 209 samples (48 seed + 161 confidence-filtered teacher labels at ≥0.70 threshold). The teacher's knowledge, compressed into the student — 91.7% accuracy, 129.9× faster.

3. **QLoRA Fine-tune (Day 4):** 4-bit NormalFloat quantized base LLM with LoRA adapters (rank-8, α=16) on query/value projections. Trained on Colab T4 GPU for 3 epochs on the same 209 distilled samples. The final candidate — 91.7% accuracy, 82.9× faster, both gates GREEN.

## 8. Failure Analysis

This is mandatory. Here's where the model is worst — named and specific.

### 8.1 — Worst Confusion: `set_timer` → `create_task`

- **Golden example:** `"count down 20 minutes for tea"`
- **True label:** `set_timer`
- **Predicted:** `create_task`
- **Latency on this sample:** 85.0 ms (highest in the set — the model hesitated)
- **Why:** The phrase "count down 20 minutes" lacks explicit trigger words like "set timer" or "alarm." The imperative "count down" reads as an action/task to the model. The LoRA adapter, trained on only 209 examples, never saw countdown-style timer synonyms in the training set.

### 8.2 — Multilingual Gaps

OXODIN is genuinely multilingual. This small router almost certainly is not. Consider:

- **German:** `"Ruf Mama an"` (= "call mom") — likely routed to `out_of_scope` because the `all-MiniLM-L6-v2` embedder and the LoRA adapter were trained exclusively on English text. The model has never seen German phone-call verbs.
- **Albanian:** `"Vendos kohëmatësin për 10 minuta"` (= "set a timer for 10 minutes") — same problem. No Albanian training data exists in the 209-sample pool.
- **French:** `"Rappelle-moi d'acheter du lait"` (= "remind me to buy milk") — `create_task` intent, but likely misrouted because French imperative structures weren't in the training distribution.

The 14B teacher handles all of these correctly because it was pre-trained on multilingual corpora. Our small router cannot.

### 8.3 — Where the 14B Still Wins

The 14B beats our router in at least three areas:

1. **Multi-intent utterances.** `"Call the dentist and set a timer for 30 minutes"` carries two intents — our single-label classifier can only pick one. The 14B returns `{"intents": ["place_call", "set_timer"]}`.
2. **Ambiguous countdown/timer synonyms.** As shown above, the 14B correctly classifies `"count down 20 minutes for tea"` as `set_timer`. Our router does not.
3. **Non-English utterances.** Any language other than English is a coin flip for our router. The teacher handles it.

## 9. Honest Caveats

These are not fine print. Each one is a place a casual reader might over-claim on our behalf.

1. **Single-label vs multi-label.** Our router picks **one intent per sentence**. OXODIN's production classifier is multi-label — it returns `{"intents": [...]}` because one utterance can carry several. We did not match that range.

2. **The k-NN router is in-dev / NO-GO.** The `bge-m3` semantic lane is default OFF and has not passed the precision bar to ship. It is not live in production — nothing here changes that.

3. **The Qwen3-4B classifier is not shipped.** There is no dedicated small classifier in OXODIN production. The Qwen3-4B split is a plan. The live baseline remains `Qwen3-14B-AWQ` for everything.

4. **Colab-trained, not prod-deployed.** Our QLoRA adapter was trained on a borrowed T4 GPU on Google Colab. We proved a result; we did not deploy a service. There is no model artifact running in production.

5. **The proxy dependency.** Anything that calls the real models goes through the OXODIN inference proxy — which returns `503` until it's configured. Our demo states plainly what it actually runs: cached golden-set predictions, not a live model endpoint.

---

## 10. What I'd Do Next

1. **Expand training data** — 209 samples is tiny. Generate 2,000+ teacher-labelled examples across all six intents, including countdown/timer synonyms, multilingual utterances, and multi-intent edge cases.

2. **Multi-label classification** — Switch from single-label argmax to a multi-label sigmoid head so the router can return `["place_call", "set_timer"]` on compound utterances.

3. **Multilingual fine-tuning** — Replace `all-MiniLM-L6-v2` with a multilingual sentence-transformer (e.g., `paraphrase-multilingual-MiniLM-L12-v2`) and include German, Albanian, and French examples in the training pool.

4. **Production deployment** — Serve the QLoRA adapter behind a FastAPI endpoint with proper health checks, request logging, and a gradual traffic ramp (shadow mode) before replacing the 14B in production.

5. **Continuous evaluation** — Set up an automated golden-set regression test in CI so any model update is immediately checked against the frozen contract before deployment.

## Reflection

Across the entire eight weeks, the **biggest honest win came from distillation** (Day 3). The raw accuracy jump from 83.3% (SetFit on 48 examples) to 91.7% (distilled student on 209 examples) was the single largest lift in the capstone — a +8.4 percentage-point gain driven entirely by using the teacher's knowledge to expand the training pool with confidence-filtered labels. QLoRA matched that accuracy but didn't exceed it; the data was the real differentiator. The numbers on my scorecard prove it: more and cleaner data beats a fancier architecture every time.
